# Interaction with PYNQ Libraries

## Overview
PYNQ (Python productivity for Zynq) is a framework that simplifies the use of Zynq-based platforms by providing Python APIs for hardware interaction. It supports a wide range of peripherals and overlays, enabling efficient development for embedded systems and adaptive computing platforms.

## Key Features
- **Peripheral Support**: PYNQ supports peripherals such as SPI, IIC, UART, Video, USB, GPIO, and more.
- **Programmable Logic (PL)**: Allows the use of programmable logic for custom hardware designs.
- **Overlays**: Pre-designed hardware configurations that can be loaded dynamically.
- **Python APIs**: Simplifies interaction with hardware components.

## Supported Peripherals
- **GPIO**: General Purpose Input/Output pins for buttons, switches, and LEDs.
- **Video**: HDMI input and output.
- **Sensors and Actuators**: Includes support for Pmod and Arduino interfaces.
- **USB**: Drivers for webcams, WiFi peripherals, and other USB devices.

## Interaction with Overlays
1. **Loading an Overlay**:
   ```python
   from pynq import Overlay
   overlay = Overlay("path_to_bitstream.bit")
   overlay.download()
   ```

2. **Accessing IP Blocks**:
   ```python
   ip_block = overlay.ip_dict['block_name']
   ```

3. **Memory-Mapped IO (MMIO)**:
   ```python
   from pynq import MMIO
   mmio = MMIO(base_addr, size)
   mmio.write(offset, value)
   data = mmio.read(offset)
   ```

## PYNQ Libraries
- **AxiGPIO**: For GPIO control.
- **DMA**: Direct Memory Access for high-speed data transfer.
- **Logictools**: For custom logic designs.
- **MicroBlaze Subsystem**: For soft real-time processors.
- **Interrupts**: For handling hardware interrupts.

## Example: Using DMA
```python
from pynq.lib import DMA
from pynq import allocate

data = allocate(shape=(1024,), dtype=np.uint32)
dma = DMA("dma_name")
dma.sendchannel.transfer(data)
dma.recvchannel.transfer(data)
```

## Detailed Interaction with PYNQ in the Codebase

### 1. ADC (Analog-to-Digital Converter) Interaction
The `readout_adc_classes.py` file manages ADC operations using PYNQ APIs:
- **AxiGPIO**: Used to control GPIO pins for starting and stopping FIFO capture.
- **MMIO**: Used to configure ADC parameters such as source selection, filter bypass, and theta values.
- **DMA**: Handles data transfer from the ADC to memory.

#### Key Methods:
- **`init_all_params`**: Initializes ADC parameters like source selection, filter bypass, and theta.
- **`start_readout`**: Starts the readout process by enabling the start register and launching the DMA streamer thread.
- **`dma_streamer_thread`**: Handles the DMA streaming process, including data transfer and streaming to a remote host.

#### Example:
```python
self._start_reg.mmio.write(0x0, 1)  # Start FIFO capture
self.set_adc_src_sel(self._adc_input_sel)  # Set ADC source selection
self.set_filter_bypass(self._adc_fil_bypass)  # Configure filter bypass
```

### 2. DAC (Digital-to-Analog Converter) Interaction
The `dac_Classes.py` file manages DAC operations using PYNQ APIs:
- **MMIO**: Used to load waveform data into BRAM and configure DAC parameters.
- **MixerSettings**: Configures the DAC's NCO frequency, phase, and Nyquist zone.

#### Key Methods:
- **`load_wave`**: Loads I and Q waveform samples into the DAC's BRAM.
- **`set_nco_freq`**: Sets the NCO frequency for the DAC.
- **`set_nco_phase`**: Sets the NCO phase offset for the DAC.
- **`set_nyquist`**: Sets the Nyquist zone for the DAC.

#### Example:
- **Loading Waveform Data**:
```python
self._bram_mmio_I_lsb.write(addr_off, self.concat_samples(I_samples[x], I_samples[x + 1]))
self._bram_mmio_Q_lsb.write(addr_off, self.concat_samples(Q_samples[x], Q_samples[x + 1]))
```
- **Configuring NCO**:
```python
self._dac_handle.MixerSettings['Freq'] = freq  # Set NCO frequency
```

### 3. DMA (Direct Memory Access) Interaction
DMA is used extensively for high-speed data transfer between hardware components and memory. The `Dma` class in `readout_adc_classes.py` initializes and manages DMA operations:
- **Descriptor Buffers**: Configured to handle multiple data transfers.
- **MMIO**: Used to write to DMA registers for starting and stopping transfers.

#### Key Methods:
- **`init_dma`**: Initializes DMA by setting up descriptor buffers and enabling DMA.
- **`soft_reset_dma`**: Performs a soft reset of the DMA.

#### Example:
- **Initializing DMA**:
```python
self._dma_reg_addr.write(0x30, 0x0010)  # Enable DMA
self._dma_reg_addr.write(0x38, self._desc_buffer[0].device_address)  # Set descriptor address
```
- **Handling Transfers**:
```python
self._dma._dma_handle.mmio.write(0x34, 0x1000)  # Acknowledge transfer completion
```

## C++ Backend in PYNQ

### Purpose
The C++ backend in PYNQ is designed to handle performance-critical operations and provide efficient interaction with hardware components. It complements the Python APIs by offering a robust foundation for low-level hardware control.

### Key Features
1. **Memory-Mapped I/O (MMIO)**:
   - Provides direct access to hardware registers.
   - Enables efficient read/write operations to configure and control hardware components.

2. **Direct Memory Access (DMA)**:
   - Manages high-speed data transfer between hardware and memory.
   - Supports scatter-gather operations for efficient data handling.

3. **Interrupt Handling**:
   - Handles hardware interrupts to ensure timely responses to events.
   - Supports asynchronous operations for improved performance.

4. **MicroBlaze Subsystem**:
   - Provides support for soft real-time processors implemented in programmable logic.
   - Allows pre-compiled C++ applications to run on MicroBlaze cores.

### Integration with Python
- The C++ backend is exposed to Python through bindings, enabling developers to use high-level Python APIs while leveraging the performance of C++.
- Libraries like `MMIO`, `DMA`, and `Interrupt` are built on top of the C++ backend.

### Applications
- Configuring and controlling ADCs and DACs.
- Managing DMA transfers for data streaming.
- Implementing custom logic in programmable logic (PL) and interfacing with it.

### Advantages
- **High Performance**: The C++ backend ensures low-latency and high-throughput operations.
- **Flexibility**: Supports a wide range of hardware configurations and use cases.
- **Scalability**: Can be extended to support additional peripherals and custom IP blocks.

## MicroBlaze Real-Time Processor

### Overview
The MicroBlaze is a soft processor core designed by Xilinx that can be implemented in the programmable logic (PL) of Xilinx FPGAs. It is highly customizable and can be configured to include features such as caches, memory management units, and various peripherals. In the context of PYNQ, the MicroBlaze is used as a real-time processor to offload tasks from the main Processing System (PS) and handle time-critical operations.

### Key Features
1. **Customizability**:
   - The MicroBlaze processor can be tailored to specific application needs by including or excluding features like floating-point units, instruction caches, and more.

2. **Real-Time Processing**:
   - It is ideal for handling real-time tasks such as signal processing, data acquisition, and control loops.

3. **Integration with PYNQ**:
   - PYNQ provides support for the MicroBlaze subsystem, allowing pre-compiled applications to be loaded and executed.
   - Python APIs are available to interact with the MicroBlaze, making it easier to use in embedded systems.

4. **Peripheral Support**:
   - The MicroBlaze can interface with peripherals such as GPIO, UART, SPI, and I2C.

### How to Use MicroBlaze in PYNQ

1. **Loading a Pre-Compiled Application**:
   - Pre-compiled applications can be loaded onto the MicroBlaze using the PYNQ API.
   ```python
   from pynq import Overlay
   overlay = Overlay("path_to_bitstream.bit")
   microblaze = overlay.microblaze
   microblaze.load_program("path_to_application.elf")
   ```

2. **Interfacing with Peripherals**:
   - The MicroBlaze can be configured to control peripherals such as GPIO, SPI, and I2C.
   - For example, to control GPIO:
   ```python
   from pynq.lib import AxiGPIO
   gpio = AxiGPIO(microblaze.ip_dict['gpio'])
   gpio.write(0, 1)  # Set GPIO pin high
   ```

3. **Real-Time Data Processing**:
   - The MicroBlaze can be used to process data in real-time, such as filtering signals or controlling actuators.

4. **Custom Applications**:
   - Custom applications can be written in C or C++ and compiled for the MicroBlaze using the Xilinx SDK or Vitis.
   - The compiled `.elf` file can then be loaded onto the MicroBlaze.

5. **Communication with the PS**:
   - The MicroBlaze can communicate with the Processing System (PS) using shared memory or interrupts.

### Example: Using MicroBlaze for Real-Time Control

1. **Write a C Application**:
   - Create a simple application to toggle a GPIO pin.
   ```c
   #include "xgpio.h"
   int main() {
       XGpio gpio;
       XGpio_Initialize(&gpio, XPAR_GPIO_0_DEVICE_ID);
       while (1) {
           XGpio_DiscreteWrite(&gpio, 1, 1);
           usleep(1000000);  // 1 second delay
           XGpio_DiscreteWrite(&gpio, 1, 0);
           usleep(1000000);
       }
       return 0;
   }
   ```

2. **Compile the Application**:
   - Use the Xilinx SDK or Vitis to compile the application into an `.elf` file.

3. **Load the Application**:
   - Load the compiled application onto the MicroBlaze using PYNQ.
   ```python
   microblaze.load_program("toggle_gpio.elf")
   ```

4. **Run the Application**:
   - The application will run on the MicroBlaze, toggling the GPIO pin in real-time.

### Advantages of Using MicroBlaze
- **Offloading Tasks**: Offloads time-critical tasks from the main processor, freeing up resources.
- **Real-Time Performance**: Handles real-time operations with low latency.
- **Customizability**: Can be tailored to specific application requirements.
- **Integration**: Seamlessly integrates with PYNQ and the Zynq platform.
